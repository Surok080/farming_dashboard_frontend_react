# Склад-учёт — дизайн вкладки

Дата: 2026-08-17  
Репозиторий: `farming_dashboard_frontend_react`  
Бэкенд (контракт API): `sofit_backend_fastapi`, префикс `/warehouse_accounting`

## Цель

Новая вкладка дашборда «Склад-учёт»: движение ТМЦ за период, карточки разделов, остатки по складам. Данные приходят из 1С через уже готовые эндпоинты. Импорт, настройки и ручной запуск отчёта в этой итерации не делаем.

## Доступ

- Модуль/вкладка: `warehouse_accounting` (`is_tab = true` на бэкенде).
- Пункт меню, заголовок шапки и страница — только если право есть в `user.userInfo.tabs` и/или `user.userInfo.module` (как у мониторинга и техкарты).
- Без права вкладки нет. Запросы к API бэкенд и так закрывает `has_access_dependency("warehouse_accounting")`.
- Подпись в меню и шапке: «Склад-учёт».
- Порядок в меню: после существующих фиксированных вкладок (техкарта, поля, мониторинг, картограммы, госмониторинг).

## Подход

Один запрос движения за период, фильтры на клиенте.

Причина: `/movement` принимает только один `storage_id` / `product_id` / `section_id`, `/stock_by_storages` — только `date_to`. Мультивыбор и согласованный график иначе не сделать без правок бэкенда.

## Поток данных

Год в шапке приложения эта страница не использует: свой период, не `year`.

Поля дат в UI — `YYYY-MM-DD` (native `type="date"`). В query — `DD-MM-YYYY`. Конвертация только в `warehouseAccountingUtils.js`.

При открытии вкладки и при каждом изменении дат параллельно:

1. `GET /warehouse_accounting/dictionaries` — `products`, `storages`, `sections`.
2. `GET /warehouse_accounting/movement?date_from=&date_to=` — без id-фильтров. Даты в `DD-MM-YYYY`.
3. `GET /warehouse_accounting/sections_summary?date_from=&date_to=` — карточки.
4. `GET /warehouse_accounting/stock_by_storages?date_to=` — график без клиентских фильтров.

Период по умолчанию: `01.01.2026` … сегодня (как на бэкенде: дата начальных остатков). Поля дат сразу заполнены этими значениями, запрос уходит при монтировании.

Склады, разделы и наименования **не** уходят в query: режут уже загруженные `movement.rows`.

### Правила фильтра

Пустое множество = «все».

Строка в таблице, если одновременно:

- `storageIds` пуст **или** `row.storage_id` в `storageIds`;
- `sectionIds` пуст **или** `row.section_id` в `sectionIds`;
- `productIds` пуст **или** `row.product_id` в `productIds`.

Мультивыбор разрешён во всех трёх измерениях сразу.

`sectionIds` — одно состояние. Селект «Разделы ТМЦ» и карточки его читают и пишут. Клик по карточке добавляет или убирает id. Можно выбрать несколько карточек.

Карточки **всегда** рисуются из `sections_summary` за период. Склад и номенклатура на суммы карточек не влияют.

### График

- Нет выбранных складов, разделов и наименований — данные из `stock_by_storages` (склады, `amount`, `quantities`, `total_amount`).
- Есть хотя бы один такой фильтр — те же столбцы считаем из **отфильтрованных** строк `movement`: группировка по `storage_id`, сумма `closing_amount`, количества `closing_quantity` по `unit`. Сортировка по сумме убыванию, как в API.

Так таблица и график показывают одну выборку. Карточки при этом остаются сводкой по всем разделам за период.

## UI

Макет как на согласованном скрине.

**Шапка страницы:** бейдж «Склад-учёт», подзаголовок про учёт ТМЦ из 1С.

**Панель:**

- дата начала, дата окончания (как в мониторинге, `type="date"`);
- мультиселект «Все склады» (`dictionaries.storages`);
- мультиселект «Разделы ТМЦ» (`dictionaries.sections`);
- кнопка «Настройки» — на месте, `disabled`;
- соседняя кнопка «Выполнить» (как в мониторинге) — на месте, `disabled`.

Смена дат перезапрашивает четыре эндпоинта. Отдельной кнопки запуска нет.

**Карточки** в ряд (семена, удобрения, СЗР и т.д. — состав с бэкенда, не хардкод):

- название раздела;
- остаток в единицах, например `165 л  687 кг` (`closing_quantities`);
- сумма остатка, ₽ (`closing_amount`);
- выбранное состояние визуально отличается;
- кликабельны.

**Таблица** «Движение ТМЦ: приход, расход и остаток ТМЦ на складе»:

- слева мультиселект «Все наименования»;
- справа «Последняя операция — DD.MM.YYYY» из `last_operation_date`; если `null` — подпись скрыта.

Колонки:

| Группа | Поля |
|---|---|
| Наименование | `product_name` |
| Склад | `storage_name` |
| Нач. остаток | кол-во (`opening_quantity` + `unit`), сумма (`opening_amount`) |
| Приход | кол-во, сумма, **i** |
| Средняя цена | `avg_price` (если `null` — «—») |
| Расход | кол-во, сумма, **i** |
| Кон. остаток | кол-во, сумма |

**i** у прихода — только если `income_quantity` или `income_amount` ≠ 0. У расхода — только если расход ≠ 0.

Суммы: пробел как разделитель тысяч, запятая в дробной части, суффикс **₽**. Количество — значение из ответа с единицей строки.

**Модалка по i:** `GET /warehouse_accounting/movement/documents` с `storage_id`, `product_id`, `income` (`true` = приход, `false` = расход), тем же `date_from` / `date_to`. Заголовок: наименование, склад, тип. Таблица: дата, название документа 1С, количество, сумма.

**Правая панель:** «Учёт запасов по складам (местам хранения)»:

- круговая диаграмма долей по `amount` — `react-google-charts` `PieChart` (уже в проекте);
- под ней список складов: цветная метка, название, количества по единицам, сумма ₽, горизонтальная полоса доли от максимума. Это разметка, не вторая chart-библиотека.

## Ошибки и пустые состояния

- Загрузка периода: индикатор на таблице, карточках и графике.
- Падение одного из четырёх запросов: снекбар, остальные успешные блоки остаются.
- Модалка: свой спиннер и своя ошибка внутри окна, страница не сбрасывается.
- Нет строк после фильтра: «Нет строк по выбранным фильтрам», если фильтры непусты; иначе «Нет данных за выбранный период».
- Нет карточек — ряд пустой, без заглушечных названий.
- Нет складов для графика — пустая панель, не нулевой круг.

## Вне скоупа

- Рабочие «Настройки» и «Выполнить».
- Импорт из S3, журнал импортов.
- Правки бэкенда (массивы id в query).
- Автотесты (в репозитории их нет).

## Проверка вручную

1. Без `warehouse_accounting` вкладки нет; с правом — есть, страница открывается.
2. По умолчанию период `01.01.2026`–сегодня, данные грузятся сразу.
3. Смена дат перезапрашивает четыре эндпоинта.
4. Мультивыбор складов, разделов, карточек и наименований режет таблицу и график; суммы карточек не меняются.
5. Карточка и селект разделов синхронны.
6. **i** открывает документы прихода и расхода за тот же период.
7. Пустой период и «всё отфильтровано» показывают разные заглушки.
8. Неактивные кнопки видны и не кликаются.
