# Мониторинг: автофильтр — дизайн

Дата: 2026-10-23  
Репозиторий: `farming_dashboard_frontend_react`  
Контракт API: `sofit_backend_fastapi`, ветка `update_monitoring`

## Цель

Разметить строки мониторинга пятым статусом, вынести пороги из автоотчёта в отдельные настройки и показать на списке, почему строка прошла или не прошла фильтр. История статусов, поиск по таблице, группировка всех строк сразу и отладочный `POST /monitoring/filter/run` в эту задачу не входят.

## Подход

Меняем существующий экран мониторинга и его диалог настроек. Новых маршрутов нет. Пороги и отчёт сохраняются двумя запросами из одной формы. Причина решения автофильтра живёт в легенде под таблицей, не в карточке строки.

Список `GET /monitoring` не отдаёт группу на строке и не отдаёт `auto_filter_result`. Поэтому заголовок группы появляется только когда группа выбрана в фильтре, а подробная легенда запрашивает `GET /monitoring/{id}` для одной отмеченной строки.

## Статусы

| Код | Подпись | Цвет строки | Кто ставит |
|---|---|---|---|
| `RAW` | Сырая строка | оранжевый значок, как сейчас, без заливки строки | импорт |
| `CONFIRMED` | Подтверждённая | зелёная галочка, как сейчас | автофильтр и человек |
| `PARTIALLY_CONFIRMED` | Подтвержден частично | салатовый значок `#7aa93c`, фон строки `rgba(122, 169, 60, 0.18)` | только автофильтр |
| `CANCELED` | Отменённая | красный значок, фон строки `rgba(211, 47, 47, 0.12)` | автофильтр и человек |
| `READY_FOR_1C` | Готово к отправке в 1С | синий значок, как сейчас | человек |

`PARTIALLY_CONFIRMED` добавляется в фильтр статуса и в счётчики зелёной полосы (`status_counts`). Кнопки, которая ставит этот статус, нет. Запрос с ним вернёт 400.

Рамка карточки у частичного статуса салатовая.

## Кнопки статуса

Набор кнопок прежний: «Сырой статус», «Отклоненный», «Подтвержденный», «Опубликовать в 1с». Текущая кнопка остаётся нажатой и недоступной. У `PARTIALLY_CONFIRMED` ни одна из четырёх не является текущей: рядом показывается салатовая подпись «Подтвержден частично».

| Из статуса | Доступны человеку |
|---|---|
| `RAW` | подтвердить, отклонить |
| `PARTIALLY_CONFIRMED` | сырой, отклонить, подтвердить |
| `CONFIRMED` | сырой, опубликовать в 1С |
| `CANCELED` | сырой |
| `READY_FOR_1C` | переходов нет |

Подтверждение и публикация в 1С требуют водителя, техоперацию и прицеп. Иначе snackbar показывает `detail` ответа 400. Из отклонённой в подтверждённую человек идёт двумя шагами: сначала «Сырой статус», потом «Подтвержденный».

Объединение и публикация в 1С с шапки — только если все выбранные строки `CONFIRMED`. Отправка в MAX — если все выбранные строки одного из статусов `CONFIRMED`, `PARTIALLY_CONFIRMED`, `READY_FOR_1C`.

## Список

Тулбар:

- Фильтр статуса, включая «Подтвержден частично».
- Фильтр «Группа техники». Пункт «Все» и группы из `equipment_groups` ответа. Выбранный id уходит в `equipment_group_id`. Список групп не зависит от выбранной группы и статуса. Пустой `equipment_groups` оставляет только «Все».
- Пока выбрано «Все», таблица плоская. Когда группа выбрана, над строками одна строка-заголовок с названием этой группы.
- Тумблер «Автофильтрование строк» пишет `enabled` сразу в `POST /monitoring/filter-settings`, вместе с уже загруженными порогами. Если настройки ещё не загружены или `GET` вернул 404, уходят значения по умолчанию из раздела «Настройки». Выключение гасит отчёт на бэкенде, после ответа настройки отчёта перечитываются. Значок информации открывает диалог настроек. Страница при открытии читает `GET /monitoring/filter-settings`, чтобы тумблер знал текущее `enabled`.
- Поле поиска не добавляется.
- Выпадающие списки «Сортировка» и «Порядок» из тулбара убираются. Сортировка переносится на заголовки колонок.

`source_changed_at` не `null`: в строке списка пометка «Данные в SMSR изменились» и дата в формате `DD.MM.YYYY HH:mm`. Пустое поле пометку не рисует.

## Сортировка по колонкам

Клик по заголовку сортируемой колонки задаёт `sort_by` и `sort_order` того же `GET /monitoring`. Бэкенд на `update_monitoring` сам упорядочивает страницу. Повторный клик по активной колонке меняет направление. У активного заголовка видна стрелка: вверх при `asc`, вниз при `desc`. Смена сортировки сбрасывает страницу на первую, как сейчас при смене списков.

По умолчанию активна колонка «Период», направление `asc`.

| Колонка | `sort_by` |
|---|---|
| Период | `period_start` |
| Геозона, поле | `field_name` |
| Сельхоз устройство | `trailer_name` |
| Тех.операция | `tech_operation_name` |
| Водитель | `driver_name` |
| Выработка, га | `area_worked` |
| Пробег, км | `mileage` |

Заголовки «Статус», «Площадь га», «Сельхоз машина» и «Ширина, м» не кликаются: в `sort_by` этих полей нет. Клиентская сортировка текущей страницы не добавляется.

## Легенда под таблицей

Четыре плашки всегда видны под таблицей. В карточке строки блока причины нет.

Общий вид, когда не отмечена ровно одна строка:

1. Красная. Слева «Нет данных», справа «Не прошла пороги».
2. Зелёная. Слева «Все обязательные поля заполнены», справа «Прошла пороги, обязательные поля заполнены».
3. Обычная. Слева «Не заполнены следующие обязательные поля:», справа «Прошла пороги, но чего-то не хватает».
4. Обычная. Слева «Проверьте, заполнены ли обязательные поля», справа «Нет данных для расчёта порогов, пустая строка».

Ровно одна строка отмечена чекбоксом: запрашивается `GET /monitoring/{id}`. Учитывается только последний выбранный id. Пока ответ не пришёл, остаются общие тексты. `auto_filter_result` равен `null` или запрос упал — тоже общие тексты, ошибка запроса показывается snackbar отдельно. Несколько отмеченных строк снова показывают общие тексты.

Если снимок есть, активной становится одна плашка, остальные остаются короткими:

| Статус строки | Активная плашка | Что дописывается |
|---|---|---|
| `CANCELED` | 1 | проверки с `passed: false`: название, значение, минимум и максимум, если он есть |
| `CONFIRMED`, `READY_FOR_1C` | 2 | без дополнительного списка |
| `PARTIALLY_CONFIRMED` | 3 | имена из `missing_fields` |
| `RAW` | 4 | параметры, у которых `value` равен `null` |

Имена полей: `driver` — водитель, `tech_operation` — техоперация, `trailer` — прицеп. Имена проверок: `agro_zone_percent` — агрозона, %, `visit_duration` — время визита, секунды, `speed` — скорость, км/ч. Проверка с `value: null` считается пройденной и в список провалов не попадает.

## Карточка строки

Редактирование разрешено в `RAW`, `CONFIRMED` и `PARTIALLY_CONFIRMED`. `READY_FOR_1C` и статусы отправки в 1С остаются закрытыми.

У `CONFIRMED` нельзя очистить `driver_id`, `tech_operation_id` или `trailer_id`. Ответ 400 показывается текстом `detail`.

Если после сохранения у `PARTIALLY_CONFIRMED` заполнены все три поля, строка перезапрашивается. Статус становится `CONFIRMED` без отдельной кнопки.

`is_track_loading === true`: на месте карты текст «Трек загружается». Карточка запрашивается снова каждые 2 секунды, пока диалог открыт и флаг истинный. Закрытие диалога опрос останавливает. Ошибка запроса останавливает опрос и один раз показывает snackbar.

`source_changed_at` не `null`: та же пометка в шапке карточки.

## Настройки

Один диалог, две колонки. «Закрыть» отбрасывает несохранённые правки фильтра и отчёта.

Слева:

- Предупреждение об ответственности за автоматические решения.
- «Автозагрузка данных». Тексты блока остаются текущими. Тумблер автоскачивания срабатывает сразу, своим запросом, и в кнопку «Сохранить» не входит. Кнопка «Скачать за вчера» видна только при `userInfo.role === "super_admin"`.
- «Автоматизированные уведомления». Подпись: «Ежедневная отправка в MAX строк, которые разметил автофильтр». Тумблер отчёта и время `send_time`. Допустимо с 05:00 до 22:00. Пока автофильтр выключен, тумблер отчёта недоступен. Подсказка текстом: «Чтобы отчёт уходил в MAX, подключите бота в Настройки → Уведомления». Отдельный переход по клику не делается: страница настроек открывается с первой вкладки и не принимает параметр вкладки.

Справа:

- «Автофильтрование строк». Тумблер и три порога. Пока тумблер выключен, поля порогов недоступны.

`GET /monitoring/filter-settings` и `GET /notifications/auto-report/settings` с ответом 404 ошибкой не считаются. Форма тогда показывает: фильтр выключен, агрозона 1 %, интервал 00:00:10, скорость от 5 до 15 км/ч, отчёт выключен, время 07:30.

«Сохранить» сначала пишет фильтр, затем отчёт.

`POST /monitoring/filter-settings` принимает `enabled`, `min_agro_zone_percent` (число от 0 до 100, дробное допустимо), `min_visit_interval_seconds` (целое, ввод по-прежнему `ЧЧ:ММ:СС`), `min_speed_kmh` и `max_speed_kmh` (дробные допустимы). Поле `updated_at` не отправляется. Если минимум скорости больше максимума, запрос не уходит, под полями пишется предупреждение.

`POST /notifications/auto-report/settings` принимает только `enabled` и `send_time`. Четыре порога в это тело больше не входят. Если в той же форме фильтр выключается, отчёт сохраняется с `enabled: false`. Время вне 05:00–22:00 на сервер не уходит, под полем пишется, что нужно это окно.

Ответ 409 при включении отчёта показывается текстом `detail`: нет бота MAX или выключена фильтрация.

Тумблер на странице списка и тумблер в диалоге меняют одно и то же `enabled`. Диалог модальный, поэтому со страницы его не переключают, пока он открыт.

## Ошибки

Snackbar показывает `detail` как есть для 400 и 409. Прочие сбои идут через уже существующий разбор ошибки API. 404 на две ручки настроек snackbar не вызывает.

## Проверка

Тестового набора во фронте нет. После реализации: `vite build` и проход в браузере.

- Фильтр статуса и счётчик видят `PARTIALLY_CONFIRMED`, кнопки этого статуса нет.
- Группа «Все» оставляет плоскую таблицу. Выбранная группа шлёт `equipment_group_id` и показывает один заголовок.
- Клик по «Период», «Геозона, поле», «Сельхоз устройство», «Тех.операция», «Водитель», «Выработка, га» и «Пробег, км» меняет `sort_by`. Повторный клик меняет `asc`/`desc`, список запрашивается с первой страницы. «Статус», «Площадь га», «Сельхоз машина» и «Ширина, м» запрос не меняют.
- Легенда общая без единственной отметки и подробная для одной отмеченной строки со снимком.
- Карточка частичной строки редактируется, в 1С и в объединение не идёт, в MAX идёт. Дозаполнение трёх полей после сохранения делает её зелёной.
- Трек с `is_track_loading` перезапрашивается и перестаёт, когда флаг стал ложным или диалог закрыт.
- Пометка SMSR видна в списке и в карточке только при заполненном `source_changed_at`.
- 404 настроек показывает значения по умолчанию. Сохранение пишет пороги и отчёт в разные адреса. Выключенный фильтр не даёт включить отчёт. Время вне окна не отправляется. Кнопка скачивания за вчера есть только у `super_admin`.
